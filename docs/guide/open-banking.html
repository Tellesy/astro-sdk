Open Banking Consent ​

Astro Open Banking SDKs use OAuth 2.0 Authorization Code with PKCE. The merchant or TPP requests access; the customer sees a hosted consent screen; the backend exchanges the returned code for scoped tokens.

Consent request ​

ts
const consent = await astro.openBanking.createConsent({
  bankId: 'andalus',
  scopes: ['accounts:read', 'balances:read', 'transactions:read'],
  purpose: 'Show your account balance before checkout',
  redirectUri: 'https://merchant.example.com/ob/callback',
  codeChallenge,
  codeChallengeMethod: 'S256',
  expiresInDays: 90,
})

Credit & Finance requires explicit finance scopes. Do not reuse a generic account consent for finance eligibility:

ts
const financeConsent = await astro.openBanking.createConsent({
  bankId: 'andalus',
  scopes: [
    'accounts:read',
    'balances:read',
    'transactions:read',
    'credit_assessment:read',
    'income:read',
    'liabilities:read',
    'affordability:read',
  ],
  purpose: 'Check eligibility for a six-month financed checkout offer',
  redirectUri: 'https://merchant.example.com/finance/callback',
  codeChallenge,
  codeChallengeMethod: 'S256',
  expiresInDays: 30,
})

What the customer should see ​

SectionRequirement
Who is askingMerchant or TPP legal name and display name.
Which bankBank name and handle.
What dataEach scope explained in plain language.
Which accountsCustomer-selected accounts, masked where needed.
DurationExpiry date and revocation path.
PurposeWhy the access is needed.

Token exchange ​

ts
const token = await astro.openBanking.exchangeCode({
  code,
  redirectUri: 'https://merchant.example.com/ob/callback',
  codeVerifier,
})

The token is scoped. Store it encrypted and rotate or revoke it when the customer disconnects access.

Astro-generated Open Banking authorization codes, access tokens, and refresh tokens are UUID-shaped opaque artifacts. Malformed token values are rejected before token-hash lookup so random bearer or refresh-token input cannot amplify database work.

Read account data ​

ts
const accounts = await astro.openBanking.accounts.list({ accessToken: token.accessToken })
const balances = await astro.openBanking.balances.get(accounts[0].id, {
  accessToken: token.accessToken,
})
const transactions = await astro.openBanking.transactions.list(accounts[0].id, {
  accessToken: token.accessToken,
  from: '2026-05-01',
  to: '2026-05-08',
})

Revocation ​

Customers must be able to revoke consent from the Astro customer portal. Banks and TPPs should also expose revocation paths where required by policy. Once revoked, future API calls must fail with an authorization error.

Security checklist ​

  • Use PKCE S256.
  • Request the minimum scopes needed.
  • Explain scopes before the customer approves.
  • Never reuse payment authorization as Open Banking consent.
  • Never reuse ordinary account access as credit-assessment consent.
  • Keep consent, payment, and recurring mandate audit trails separate.

Presented consent entry ​

If a bank or wallet launches Open Banking consent from a QR or NFC handoff, Astro should still preserve the same consent model:

  • explicit scopes
  • visible purpose
  • account selection where required
  • independent audit trail

Presented entry is only a launch method. It must not hide or compress consent disclosure.
