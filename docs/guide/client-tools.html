OpenAPI, Postman, and Client Tools ​

Astro SDKs are the recommended integration path for Neptune. Astro. The underlying protocol is OpenWave, so teams can also inspect the OpenAPI files, import them into Postman, or generate clients when they need a language that does not have a hand-written SDK yet.

When to use what ​

NeedUse
Production merchant integrationTypeScript or Kotlin backend SDK plus Web/React/Flutter/Swift client SDK.
Quick API explorationPostman or Swagger Editor with the OpenWave OpenAPI files.
Internal bank middlewareOpenWave bank callback OpenAPI plus bank-specific CBS integration code.
Unsupported languageGenerate a client from OpenAPI, then wrap it with Astro-specific configuration and security checks.
Documentation portalRedocly, Swagger UI, Stoplight Elements, or VitePress generated pages.

Postman setup ​

There are now two supported Postman approaches:

  1. import raw OpenAPI files when you only want one protocol surface
  2. import the Neptune Astro merchant project when you want a ready-to-run workspace that covers checkout, trusted merchant-hosted flows, webhooks, reports, mandates, presented payments, open banking, and finance

Use the dedicated merchant project here:

  • Merchant Postman Project
  • Collection download
  • Sandbox environment
  • Live environment

If you still want raw OpenAPI import:

  1. Open Postman.
  2. Choose Import.
  3. Choose Link.
  4. Paste the raw OpenAPI URL for the surface you want.
  5. Create an environment with the variables below.
VariableExampleUsed for
ASTRO_BASE_URLhttps://sandbox.astro.example.com/api/v1Gateway API base URL
MERCHANT_KEYmk_test_...Merchant APIs
WEBHOOK_SECRETwhsec_...Local webhook verification tests
BANK_KEYowbk_...Bank-to-identity registry APIs
INTERNAL_KEYow_cbk_...Gateway-to-bank callback smoke tests
GATEWAY_KEYowgw_...Gateway interconnect tests
FINANCE_KEYfp_test_...Credit & Finance provider APIs

Swagger UI ​

bash
docker run -p 8080:8080 \
  -e SWAGGER_JSON_URL=https://raw.githubusercontent.com/neptune-ly/openwave-spec/main/openwave-payments-v1.yaml \
  swaggerapi/swagger-ui

Open http://localhost:8080 and configure the server URL to your Astro sandbox.

Generate a client ​

Generated clients are useful for internal tooling, QA, or languages without a maintained Astro SDK. For merchant checkout, still keep the security model: merchant keys stay on your backend and customer authorization happens in hosted UI.

bash
npx @openapitools/openapi-generator-cli generate \
  -i https://raw.githubusercontent.com/neptune-ly/openwave-spec/main/openwave-payments-v1.yaml \
  -g typescript-fetch \
  -o ./generated/openwave-payments

npx @openapitools/openapi-generator-cli generate \

  -o ./generated/openwave-payments-python

Security note ​

Generated clients do not automatically enforce Astro's integration rules. Your application must still:

  • Keep merchant API keys server-side.
  • Use hosted checkout or SDK-controlled webviews for customer authorization.
  • Verify webhooks before fulfilment.
  • Use idempotency keys for mutating requests.
  • Request the minimum Open Banking scopes needed.
