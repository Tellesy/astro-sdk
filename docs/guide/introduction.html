Introduction ​

Astro is Neptune Fintech's OpenWave-compliant gateway. The SDKs in this documentation let you integrate payments, subscriptions, Open Banking consent, Credit & Finance targets, NPT identity resolution, and signed webhooks into any platform.

Astro follows one rule for secure integrations: sensitive operations start on your backend and customer authorization normally happens in Astro-hosted UI or SDK-controlled webviews. Merchants should not collect bank OTPs, push approval tokens, or Open Banking consent decisions directly inside their own pages unless Neptune has explicitly approved the separate trusted merchant-hosted checkout lane for that merchant.

The same rule now applies to presented payments. QR and NFC may start the flow, but final customer approval still happens inside Astro-hosted or bank-controlled secure surfaces.

The same rule applies to Credit & Finance. BNPL, revolving-credit, and Murabaha offers are created server-side, reviewed in hosted or official SDK UI, and settled through signed final payment states.

Ownership boundaries

Server SDKs create intent. Client SDKs open secure authorization. Astro signs the outcome.

This is the contract every SDK follows across web, React, Flutter, Kotlin, and Swift integrations.

Choose the right SDK ​

  • Backend / server-side — Use TypeScript (Node) or Kotlin (JVM/Spring)
  • Checkout widget — Use Web Drop-in (no framework) or React (React app)
  • Mobile app — Use Flutter (cross-platform) or Swift (iOS native)

Core Flow ​

Secure checkout model

The merchant starts the session. Astro hosts the customer decision.

1Backend creates session2SDK opens hosted UI3Customer uses bank SCA4Astro signs outcome5Merchant fulfils
Backend SDKcreateSession()Safe place for merchant keys.
Hosted surfaceCheckoutConsentMandate approval
Webhookpayment.completedFinal state only.
1. Merchant backend creates a PaymentSession   →  POST /payments/initiate
2. Customer is redirected to checkoutUrl       →  Astro checkout UI
3. Customer authenticates in hosted UI         →  Bank OTP or push SCA
4. Astro fires payment.completed webhook       →  Your webhook endpoint
5. Merchant fulfils the order                  →  Done ✅

Open Banking flow ​

1. Your backend creates a consent request with scopes + PKCE
2. Customer is redirected to Astro hosted consent
3. Astro shows the TPP, bank, accounts, and requested permissions
4. Customer approves with OTP or push SCA
5. Your backend exchanges the code for tokens
6. Your backend calls accounts, balances, and transactions APIs
