TypeScript / Node.js SDK ​

TypeScript   Node.js 18+

Server-side SDK for Node.js, Deno, and Bun. Tree-shakeable ESM + CommonJS dual build.

Use this SDK for anything that requires a secret: merchant API keys, Open Banking token exchange, Credit & Finance orchestration, webhook verification, recurring mandate charges, and operational reconciliation.

Install ​

bash
npm install @neptune.fintech/astro-sdk
# or
pnpm add @neptune.fintech/astro-sdk
# or
yarn add @neptune.fintech/astro-sdk

Quick Start ​

typescript
import { createClient } from '@neptune.fintech/astro-sdk'

const astro = createClient({
  baseUrl: 'https://astro.neptune.ly/api/v1',
  merchantKey: process.env.ASTRO_MERCHANT_KEY
})

// Create a payment session
const session = await astro.payments.createSession({
  amount: 50_000,     // 50.000 LYD
  currency: 'LYD',
  destination: { type: 'alias', value: 'mtellesy' },
  merchant_reference: 'order_1042',
  redirect_url: 'https://myapp.com/checkout/result',
  webhook_url: 'https://myapp.com/webhooks/astro'
}, {
  idempotencyKey: 'order_1042_create_session'
})

console.log('Redirect customer to:', session.checkout_url)

Refunds ​

Refunds are server-side payment resources. Use them only from trusted merchant backends, after the original session has completed.

typescript
const refund = await astro.payments.createRefund(
  session.session_id,
  {
    amount: 50_000,
    currency: 'LYD',
    reason: 'Customer return',
    merchant_reference: 'refund_order_1042_001'
  },
  { idempotencyKey: `refund_${session.session_id}_001` }
)

const current = await astro.payments.getRefund(refund.refund_id)
const allForPayment = await astro.payments.listRefunds(session.session_id)

Use a unique idempotency key per refund attempt, refund only completed sessions, and reconcile from signed refund.completed or refund.failed webhooks. Never issue refunds from browser or mobile code because merchant credentials stay server-side.

astro.alias ​

typescript
// Resolve an alias to IBAN + bank
const resolved = await astro.alias.resolve('mtellesy')
// { nptHandle: 'mtellesy', iban: 'LY83...', bankHandle: 'andalus' }

// Get alias profile
const profile = await astro.alias.get('mtellesy')

// Get linked accounts
const { accounts } = await astro.alias.getAccounts('mtellesy')

// Availability and rename require a bank key and must run on a bank server.
const bankAstro = createClient({
  baseUrl: 'https://astro.neptune.ly/api/v1',
  bankKey: process.env.OPENWAVE_BANK_KEY
})

const availability = await bankAstro.alias.availability('mtellesy.new')
if (availability.status === 'UNKNOWN') {
  throw new Error('Identity could not be consulted; retry without renaming')
}

const renamed = await bankAstro.alias.rename({
  current_alias_username: 'mtellesy',
  new_alias_username: 'mtellesy.new',
  national_id: '123456789012'
})
console.log(renamed.previous_retired) // true; the previous name is permanent history
console.log(renamed.retired_handle)
if (renamed.reauthentication_required) {
  // Return this instruction to the authenticated bank app and end old-handle sessions.
  console.log(renamed.next_step)
}

TAKEN means a current owner holds the name; RETIRED means it can never be reused; UNKNOWN is a transport/disabled state and must never be treated as availability. A successful rename returns retired_handle, reauthentication_required: true, and Identity's next_step; do not treat the flow as complete while an old-handle portal session remains active. Keep the bank key and national ID out of browser and mobile bundles.

Presented QR / NFC handoff ​

Create presentments from a trusted backend. The merchant frontend can render the QR payload or start NFC handoff, but after claim it must open only the returned secure surface.

typescript
const presentment = await astro.presentments.create({
  channel: 'QR',
  mode: 'MERCHANT_PRESENTED',
  intent: 'ONE_TIME_PAYMENT',
  amount_mode: 'FIXED',
  amount: 125_000,
  currency: 'LYD',
  description: 'In-store checkout',
  merchant_reference: 'pos_1042'
}, {
  idempotencyKey: 'pos_1042_presentment'
})

// Render presentment.presentment_payload.uri as QR or NFC payload.

After scan or tap, claim returns payment_url, mandate_consent_url, or auth_surface. Open that secure hosted, SDK-controlled, or bank-controlled surface. Do not collect OTP, PIN, passcode, push approval, or bank credentials in merchant UI.

Production checklist ​

ControlWhy it matters
Keep merchantKey server-sidePrevents unauthorized session or mandate creation
Send Idempotency-Key on writesMakes retry behavior safe during network timeouts
Verify X-OpenWave-SignaturePrevents forged payment or mandate webhooks
Store state and PKCE verifierProtects Open Banking callback integrity
Use hosted Astro UIKeeps OTP, push approval, and consent outside merchant pages
Keep finance assessment output server-sidePrevents raw transaction-derived data leaking to merchants

astro.webhooks — WebhookReceiver ​

typescript
import { WebhookReceiver } from '@neptune.fintech/astro-sdk'

const receiver = new WebhookReceiver(process.env.ASTRO_WEBHOOK_SECRET!)

receiver.on('payment.completed', (event) => {
  const { reference, amount, settlement_type } = event.data
  console.log(`Order ${reference} paid via ${settlement_type}`)
  db.orders.markPaid(reference)
})

receiver.on('payment.failed', (event) => {
  db.orders.markFailed(event.data.reference)
})

receiver.on('finance_contract.active', (event) => {
  db.financeContracts.activate(event.data.contract_id)
})

receiver.on('repayment.failed', (event) => {
  db.repayments.markFailed(event.data.installment_number)
})

// Express
app.post('/webhooks/astro', express.raw({ type: '*/*' }), async (req, res) => {
  const sig = req.headers['x-openwave-signature'] as string
  try {
    await receiver.handle(req.body.toString(), sig)
  } catch {
    return res.sendStatus(401)
  }
  res.sendStatus(200)
})
