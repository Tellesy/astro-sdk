Web Drop-in Widget ​

Browser   No framework required

Add a complete Astro-hosted authorization surface to any website with one script tag. No framework. No build step.

Use the Web SDK when you want the browser to open a secure checkout or consent surface while keeping merchant keys and Open Banking token exchange on your backend.

CDN (recommended) ​

html
<script src="https://cdn.jsdelivr.net/npm/@neptune.fintech/astro-web/dist/astro.umd.cjs"></script>

<button onclick="launchCheckout()">Pay 500 LYD</button>

<script>
async function launchCheckout() {
  // 1. Create session on your server first.
  // Never create sessions directly from the browser.
  const { session_id } = await fetch('/api/create-payment', {
    method: 'POST',
    body: JSON.stringify({ amount: 500000, reference: 'order_1042' })
  }).then(r => r.json())

  // 2. Open the Astro checkout modal
  Astro.checkout({
    sessionId: session_id,
    gatewayUrl: 'https://astro.neptune.ly',
    onSuccess(result) {
      console.log('Paid!', result.reference)
      window.location = '/order/' + result.reference + '/success'
    },
    onFailed(err) {
      alert('Payment failed: ' + err.message)
    },
    onDismiss() {
      console.log('Customer cancelled')
    }
  })
}
</script>

npm ​

bash
npm install @neptune.fintech/astro-web
javascript
import { checkout } from '@neptune.fintech/astro-web'

document.getElementById('pay-btn').addEventListener('click', async () => {

  checkout({
    sessionId: session_id,

    onFailed: (err) => console.error(err),
  })
})

Options ​

typescript
interface CheckoutOptions {
  sessionId: string         // From your server's POST /payments/initiate response
  gatewayUrl: string        // Base URL of your Astro gateway
  locale?: 'ar' | 'en'     // Default: 'ar'
  theme?: 'light' | 'dark' // Default: 'light'
  onSuccess?: (result: { session_id: string, reference?: string }) => void
  onFailed?: (error: { code: string, message: string }) => void
  onDismiss?: () => void
}

Flow ​

1. Your server creates a PaymentSession  →  returns session_id
2. Your page calls Astro.checkout({ sessionId })
3. Astro hosted UI collects alias/IBAN and bank authentication
4. Astro processes the payment and emits signed webhook
5. onSuccess fires — redirect to your thank-you page

Open Banking consent handoff ​

Open Banking starts on your backend. Your server creates a consent request with scopes, PKCE challenge, redirect URI, and state. The browser should only receive the consent_url.

javascript
async function connectBank() {
  const { consent_url } = await fetch('/api/open-banking/consents', {
    method: 'POST',
    body: JSON.stringify({
      bank: 'andalus',
      scopes: ['accounts:read', 'balances:read', 'transactions:read']
    })
  }).then(r => r.json())

  window.location.assign(consent_url)
}

The consent page must show the customer exactly which scopes are requested before OTP or push approval.

Session creation is server-side

Never create sessions in the browser — your merchant API key would be exposed. Create sessions on your backend and pass only the session_id to the frontend.

Presented QR / NFC handoff ​

Your merchant page may show an OpenWave QR payload or expose an NFC target, but it must not become the bank authorization page. After the customer claims the presentment, open the returned payment_url, mandate_consent_url, or auth_surface.url in the hosted checkout or SDK sheet.

For QR, render the returned qr_payload.value instead of inventing a browser-only payload. In Libya deployments it is an EMV/NUMO-compatible TLV payload with LY.OPENWAVE inside tag 26 and optional operator metadata in tag 50. Normal NUMO/LYPay QR codes remain on their existing route.

For NFC, expose the returned NDEF URI/universal link and let the secure OpenWave surface handle authorization after claim.

Merchant pages must not render OTP, PIN, passcode, push approval, or bank credential inputs for bank authorization.

Credit & Finance handoff ​

The browser should not create assessments or finance offers. Your backend creates the assessment and offer, then passes only the hosted accept_url to the browser.

javascript
async function acceptFinancedOffer() {
  const { accept_url } = await fetch('/api/finance/offer', { method: 'POST' }).then(r => r.json())
  window.location.assign(accept_url)
}

Astro-hosted acceptance must show the customer amount, tenor, disclosure, repayment schedule, and Murabaha-specific terms where applicable.

import { dismiss } from '@neptune.fintech/astro-web'
